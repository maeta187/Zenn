## はじめに

以前からモバイル開発に興味を持っており Flutter も触ってみましたがやはり JS で開発したいと思い、React Native を学習しようと思いました。
昨今 AI 開発の進化が目まぐるしいので、Codex を使って学習/開発をしてみました。

## 作ったもの

賞味期限管理アプリを作りました。
皆さんはスーパーでカットネギを購入されたことはありますか？
自分の近所にあるスーパーはラベルに賞味期限が記載されていますが、そのラベルは 1 度剥がすと捨てるしかありません。
それで賞味期限を忘れて使い切れなかったことが多々あります…
メモ帳とかリマインドアプリを使えば良いと思うのですが食品に特化させたら面白いと思い作ることにしました。

@[card](https://github.com/maeta187/food-keep-watch)

### 主な機能

- 賞味期限登録機能
  - 食品名
  - 賞味期限/消費期限
  - 期限日
  - 保管場所
  - カテゴリー
  - 通知時間
- 登録情報一覧画面
- 登録情報詳細画面
  - 削除機能
  - 編集機能
- カテゴリー編集機能
- プッシュ通知機能

## Codex を使った理由

当初 Claude Code を使うか悩みました。
丁度その時期に巷で「Claude Code の精度が悪くなった。」という声を耳にしていたので元々 ChatGPT に課金していたのもあり、 Codex を使うことにしました。

### 開発時の Codex の使い方

ローカルで動かしたかったので当初は`Codex CLI`を使おうとしていましたが、エディターの拡張機能でも Codex が使えるようになっていたので、そちらを使うことにしました。

@[card](https://marketplace.visualstudio.com/items?itemName=openai.chatgpt)

### Codex の料金/制限について

自分は Plus プランに加入し、拡張機能で使用していたので追加料金は発生しませんでした。
その代わり使用制限があり上限を超えると使用できなくなります。

![ダッシュボード](/images/codex-1.png)

- 5 時間制限
- 週次制限
- コードレビュー制限
  ※コードレビューは GitHub でレビューした時に消費されます

消費量は使用モデルと作業量で変わるようです。
自分は週末や仕事が始まる前の隙間時間で使用していたので制限されると言ったこともありませんでした。

## 開発

以下の流れで開発を進めていきました。

### コンテキスト作成

何も無い状態で始めると絶対にめちゃくちゃな環境になるのでコンテキストを作成することから始めました。
調べて必要そうな項目と自分があった方が良いと思った項目を追加しました。
あとは開発しながら必要であれば更新する方針で進めました。

### バイブコーディング

今回は基本的な開発は Codex に任せて自分は動作確認などを行うがメインです。
実装の中で DB やテストが導入された時には方針などをまとめたものを`docs`ディレクトリ内に書きました。

### コードレビュー

GitHub と連携してコードレビューするように設定すれば PR が出来たタイミングで Codex が自動でレビューしてくれます。
AI が書いたコードを AI がレビューすると言う何とも言えない構造ができました笑

## バイブコーティングの感想

### 開発スピードの速さ

言わずもがなですがやはり圧倒的に早いです。
ものの数分でそれなりのものができるのでスルスルとアプリが出来て最初は楽しかったです。

### 無限レビュー編

Codex にレビューをやってもらっていたのですが重めの機能実装のレビューは延々と指摘されます。
場合によっては Codex がコードを修正してくれるのですが修正したコードを更に修正すると言ったことも発生しました。
そうなって来るとキリが無いので途中で merge していきました。

### 結局 ReactNative、Expo の仕様は理解出来ていない

いきなり開発から入ったのも悪手でしたが、AI に任せるので実装から得る経験や知識は自分で実装した場合で比べるとほとんど無かったです…
自分には学習目的でバイブコーディングするのは向かいないなと感じました。

### UI 修正に弱い

UI が思ったように出来ていない時に修正するよう指示するのですが Tailwind CSS を使っていたことも影響なのか精度はあまりよく無かったです。
自分で見てみると ReactNative のオプションと競合してスタイルが崩れていたと言ったことが多かったです。

### AI が書いたからと言って読み易いコードではない

AI がコードを書いたから綺麗なコードになるとは限りません。
寧ろ複雑になっている場合もあります。よく AI のコードをレビューするのは大変と聞きますがこう言った部分から来るんだなと実感しました。

### どう言った処理で動いているのか把握しきれていない

これは自分が悪いですが開発スピードの速さが楽しくなり、コードを読む意識が薄れていました。
「ここどう処理されている？」と質問されても答えれる自信がありません…

## リリースをするのか

結論からするとリリースしません。
セキュリティ度外視になっているので何かしらのリスクを抱えていそうです。
保守、運用も恐らく AI 任せになり、いつか大きなしっぺ返しがありそうなので。

## バイブコーディングとどう向き合うか

プライベートで使う場合は使い慣れた言語、フレームワークで何かしら開発する時に引き続き使用はします。
ただ今回のように AI に丸投げするやり方は見直す必要があります。
使いなれていない物の学習は今までのように公式ドキュメントを読む、自分で手を動かして触ってみる、それでも理解出来ない場合は AI を使うスタイルで学習していきます。
指示をするだけでコードが書かれて、アプリが出来上がっていくことは圧倒的に楽ではありますが自分の中で試行錯誤する力が失われている感じがありました。
時間が掛かっても自分で考え、トライ&エラーを繰り返して実装することも悪いことではないなと思います。
ただこれ一辺倒になると逆張り感が強いのでバイブコーディングも程よく取り入れていきます。
