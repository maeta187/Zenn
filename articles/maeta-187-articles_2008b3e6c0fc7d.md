## マルチエージェント

最近の世の中の傾向は1つのエージェントを使うのではなく複数のエージェントを組み合わせて使うことが多くなってきています。
例えば、ClaudeCodeでプランを作成して、実装はCodexに行ってもらうと言ったような使い方が多くなってきています。

### どうやってマルチエージェントを使うのか

言うのは簡単ですが、MCPで接続を行うなど工夫が必要です。
一応[codex-plugin-cc](https://github.com/openai/codex-plugin-cc)を使えばClaudeCodeからスキルを実行してCodexに渡すことができます。
ただ、他のエージェントには対応していないので限定的です。
そんな中、Herdrはマルチエージェントを簡単に使うことができるツールです。
詳しくはこの後に続きます。

## Herdrとは

色々なところで紹介はされていますが、複数のAIエージェントを使用した時の管理の複雑さを解決するために開発されたツールです。
アプリのイメージを持ちがちですが、CLIのバックグラウンドで動作するサーバーです。
スキルを活用することで自然言語でマルチエージェントを使うことができます。

@[card](https://herdr.dev/)

## 基本の仕組み

Herdrのインストールが完了したらCLIで`herdr`と入力して実行するとサーバーが起動します。
起動した大体こんな感じです。
**spaces**下に表示されているのがプロジェクトの一覧です。
エージェントを立ち上げると**agents**下に起動中のエージェントが表示されます。
右側がペインです。

![Herdr](/images/herdr-1.png)

`herdr stop`でサーバーを停止することができます。

### 基本的に動き続ける

サーバーが動いている限りセッションとプロセスは保持され、再接続すればそれらを保持した状態に戻れます。
SSH経由でリモートアタッチ可能なので以下のような用途で使うことができます。

```bash
herdr --remote [ホスト名]
```

- Mac miniでherdrサーバーを常駐させ、ノートPCは `herdr --remote`で接続する
- 重い処理をスペックが高いPCに任せる
- 複数人で接続して同じセッションを使用したペアプロ

### エージェントの状態を探さない

Herdrは立ち上がっているエージェントの状態**agents**下に一覧で並べ、それぞれのエージェントの状態をUIで確認することができます。
主な状態は以下のようになります。

![Herdr](/images/herdr-2.png)

- Running: 実行中
- idle: 待機中
- blocked: ブロック中(ユーザーが入力を待っている)
- done: 完了

移行前は複数のタブを開いて使っていたのでタブを切り替えて確認していましたが、その手間がなくなりました。
アイコンのデザインは設定で変更することができます。
また、起動中のエージェントが表示されるので今起動中のエージェントが一目でわかります。

プロジェクト単位でもエージェントの状態を確認することができます。

![Herdr](/images/herdr-3.png)

### 使用するターミナルはそのまま使える

HerdrはCLIのバックグラウンドで動作するサーバーなので今使用しているターミナルはそのまま使えます。
※ Herdr使うにあたってをtmuxから別のターミナルに移行した記事はよく見かけます。
ただ1つだけ相性の悪いターミナルがあります。
それは**Warp**です。
WarpもTUIツールなのでHerdrと競合を起こし、Herdr側の機能が動作しなくなりました。
なので前に試しに使っていた**cmux**に移行しました。
~~ghosttyに移行するのが面倒だった~~
まずはいつも使っているターミナルで試すで良いと思います。

### エージェントネイティブ

人間が叩くCLI とエージェントが叩くUnixドメインソケット API は共通なのでherdrの操作をコマンドで実行かつ、エージェントもherdrを操作可能です。
自分もUnixドメインソケット API がなんなのかと言われるとあまりちゃんとした説明ができなかったので図にしてみました。

![フロー図](/images/herdr-4.png)

人間とエージェントが同じ経路を辿っているのと、herdrサーバーにはUnixドメインソケット API でアクセスしているので、人間もエージェントもHerdrの操作が可能になっています。

公式のskillを導入することでペインを分割し、自然言語で片方のペインを見てタスクを実行するといったことも可能です。

> 例
> 実装が完了したら下のペインにレビューを出して
> 上のペインからレビュー依頼がくるので待機し、レビューが完了したら上のペインに結果を出して
> ※これはトークンを焼き切るプロンプトなので工夫が必要です

@[card](https://herdr.dev/ja/docs/agent-skill/)

### 対応しているエージェント

`Claude Code`、`Codex`、`Cursor`、`Devin`、`Grok`、`Kimi`、`Hermes Agent`など合計20以上のエージェントに対応しています。
対応状況については随時更新されると思うので[Supported agents](https://herdr.dev/docs/agents/#supported-agents)を参照してください。

### tmuxとの違い

自分がtmuxを使ったことが無いのでAIの力を借りて比較してみました。

|                    | tmux                                 | herdr                                      |
| ------------------ | ------------------------------------ | ------------------------------------------ |
| 想定する利用者     | 人間が手で分割する汎用マルチプレクサ | エージェント前提で設計されたマルチプレクサ |
| エージェントの状態 | ペインを覗いて確かめる必要がある     | working / blocked / done / idle を自動判定 |
| 自動化             | `send-keys` でキー入力を投げて祈る   | エージェント単位の API。完了まで待つ       |
| worktree           | 手作業で行う必要がある               | worktree を標準機能として搭載している      |

### 続きから戻る

1. デタッチと再アタッチ
   tmux と同じようにデタッチ、再アタッチが可能です。

2. 再起動後のレイアウト復元
   ワークスペース、タブ、ペイン、カレントディレクトリなどが復元されます。

3. エージェントの会話も再開
   デタッチ、再アタッチ後もエージェントの会話が再開されますが、基本的に`herdr stop`やターミナルを閉じる、PC再起動でherdr内のセッションは終了します。
   ただし、エージェント側がセッションの復元に対応かつ、herdr側で対象のインテグレーションをインストールすることで復元することが可能です。
   エージェント側がセッションの復元はClaudeCodeで言うと`--resume [session_id]`オプションが該当します。
   他のエージェントも同等の機能が用意されていたらherdrを立ち上げた時にそのペインで最後に起動していたエージェントを自動的に`--resume [最後に開いていたセッションのsession_id]`をオプションを付けて起動してくれます。

@[card](https://herdr.dev/docs/integrations/)

## 設定とカスタマイズ

基本的にゼロコンフィグで動作しますが、自分好みに設定することでより自分好みに使うことができます。
TUIの`menu`→`settings`から設定を変更することもできますが、より細かい設定をする場合は設定ファイルを編集します。

### 設定ファイル

設定ファイルはデフォルトでは下記のディレクトリに配置されます。

#### Linux / macOS

```bash:terminal
~/.herdr/config.toml
```

#### Windows

```bash
%APPDATA%\herdr\config.toml
```

詳しい設定については公式ドキュメントを参照して欲しいのですが、下記のように設定します。

```toml:config.toml
[theme]
name = "catppuccin"
```

@[card](https://herdr.dev/ja/docs/config-reference/)

#### 設定の反映

設定ファイルが更新してからはHerdrの再起動もしくは、設定ファイルをリロードすることで設定が反映されます。
再起動はセッションが終了するので設定ファイルをリロードすることをおすすめします。

設定ファイルのリロードは`herdr serve reload-config`を実行または、TUIの`menu`→`settings`から`reload config`をクリックすることで設定が反映されます。
正しく設定できていたら反映されますが、間違った設定を行なっている場合はリロード時に`config.toml; herdr config check`で警告が表示されます。
不正な値は安全な既定値に戻るか無視されます。

### キーはtmuxと同じ

Herdrはtmuxと同様にプレフィックスを使用して操作を行うことができます。

#### プレフィックスについて

プレフィックスは特定のキーを押した後キーを押して操作を行います。
Herdrの場合は`ctrl+b`をプレフィックスとして使用します。
例えば`ctrl+b`を押した後に`q`を押すと`herdr quit`を実行します。
こうすることで、ターミナルやエディタの入力を奪わず操作することが可能です。
プレフィックスも設定ファイルで変更することができます。

```toml:config.toml
[keys]
prefix = "ctrl+a"
```

### UIのカスタマイズ

UIもテーマ、アイコン、サイドバーの表示、通知方法などを設定ファイルで変更することができます。

## プラグイン

プラグインを追加することでHerdrを拡張することができます。

@[card](https://herdr.dev/ja/docs/plugins/)

### プラグインで拡張

マーケットプレイスからGitHubのリポジトリに遷移してREADMEに沿ってプラグインをインストールすることができます。
注意していただきたいのが公開時にソースコードの検証などは全く行なっていないので、入れる際は確認してインストールしてください。
安全を期すならインストールせず自分で作る方が良いと思います。

@[card](https://herdr.dev/ja/docs/marketplace/)

### プラグインを公開

公開はリポジトリに`herdr-plugin.toml` ファイルを置き、GitHub のトピックに `herdr-plugin` と付けるだけで公開可能。索引は 30 分ごとに更新されます。
マニフェストを検証するだけで、中身のレビューやサンドボックス化もせず審査もないので安易にトピックに `herdr-plugin` を付けないよう気を付けてください。

### RaycastからHerdrを操作

Raycastを使用している人はプラグインを追加するとRaycastからHerdrを操作することができます。
個人で開発されたものなので自己責任で使用してください。

@[card](https://www.raycast.com/vlades/herdr)

## Worktreeで並列化

同じブランチで並列で作業を行うとエージェント同士が同じファイルを更新してコンフリクトを起こしてしまうのでWorktreeを使用して並列作業を行うことができます。

### Worktree標準搭載

HerdrはWorktreeを標準搭載しているので追加で設定を行なうことなく使用することができます。

### CLI/TUIから作成

HerdrはCLI/TUIからWorktreeを作成することができます。

```bash:terminal
$ herdr worktree create --label [ラベル名]
$ herdr worktree create --branch [ブランチ名]
$ herdr worktree create --label [ラベル名] --branch [ブランチ名]
$ herdr worktree open --workspace [ワークスペースID]
$ herdr worktree list
$ herdr worktree remove --workspace [ワークスペースID]
```

TUIから作成する場合はプロジェクトを右クリックして `New worktree` / `Open worktree`
から作成、開くことができます。

### Worktreeの管理

Worktreeの置き場所は`~/.herdr/worktrees`がデフォルトですが、設定ファイルで変更することができます。

```toml:config.toml
[worktree]
directory = "~/.herdr/worktrees"
```

### Worktreeの削除

Worktreeを削除する場合は`herdr worktree remove --workspace [ワークスペースID]`を実行します。
閉じても作業ディレクトリは残り。削除してもブランチは消さないよう設計されています。

## 具体的な使い方

#### プライベート

自分はプライベートだと上下でペインを開いて上がClaudeCode、下がCodexを使っています。
ClaudeCodeでプラン、実装してCodexでレビューを行っています。
レビューのプロンプトはざっくり下記のようにやっています。

```markdown:ClaudeCodeのプロンプト
下のペインから修正依頼が来るので待機してください。
修正後再度下のペインにレビュー依頼を出してください。
再度修正依頼が来るので待機してください。
```

```markdown:Codexのプロンプト
このブランチで作業した内容を敵対的にレビューしてください。
修正依頼は上のペインに依頼してください。
上のペインから再度レビュー依頼が来るので待機してください。
最大5回までレビューを行い、終了時には上のペインにも終了するよう伝えてください。
```

`上`とか`下`とか雑な自然言語でも自律的にレビュー、修正を繰り返すことができます。
安定して動いているのでスキル化する予定ですが、より複数のペインを開くと意図して動くか分からないのでそう言った場合はさらに工夫が必要です。
`ペインを一覧化`と言ったプロンプトを実行するとHerdr内で開いているペインが一覧で表示されるのでそちらもスキル化して上手く組み合わせたらより良いものが作れるかもしれません。

#### 社内プロジェクト

社内プロジェクトではアプリ、AWS、仕様駆動開発を行うためのドキュメントリポジトリがそれぞれ分かれています。
前まではドキュメントリポジトリから実行し、上手くいかない時はパスを渡して実行していました。
Herdrを使い初めてからはそれぞれのリポジトリでエージェントを立ち上げて、ドキュメントリポジトリを起点に各リポジトリのエージェントに指示を出して実装を行っています。
レビューは各リポジトリのエージェントに指示を出して行っています。
